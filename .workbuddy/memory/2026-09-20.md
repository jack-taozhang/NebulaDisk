7. 无环境变量的配置项：`kk.Getcorsfile`、`file.upload.disable`、`kk.scriptjs`、

8. 5.0.x 强制 JDK 21+；基础镜像 tag 长期是 5.0.0，不存在 `-base:5.0.2`。

### 构建结果

### 三项稳定性加固（本轮新增，均已实测生效）
1. **`shm_size: 2gb`**（compose）—— Docker 默认 `/dev/shm` 仅 64MB，是 soffice SIGABRT 主因。
   实测 `ShmSize=2147483648`。
2. **`OFFICE_PLUGIN_SERVER_PORTS: "2001"`** —— 官方默认 `2001,2002` 双实例并行冷启动互相抢占：
   日志表现为两个实例先 `exit 81`，重试后一个变 `exit 134` 彻底废掉，
   **并发容量反而从 2 降到 1**。单实例后 `exit code 134` 计数 **0**。
   注意必须用「大写+下划线」环境变量名（源码是 `@Value("${office.plugin.server.ports:2001,2002}")`，
   靠 Spring relaxed binding 命中）。
3. **关闭 core dump** —— `limits.conf` 写 `core 0` + `ENTRYPOINT` 里 `ulimit -c 0` 兜底
   （`limits.conf` 对已运行的 PID 1 不生效，两层都要）。原状态下 `ulimit -c=unlimited` +
   `core_pattern=core`，每次 SIGABRT 都会往工作目录写几百 MB 的 core，撑爆 data 卷。

> 残留的 1 次 `exit code 81` 属 jodconverter 自带探活重试（首进程启动偶慢），**良性**，不必追求 0。

### ★ 本轮最重要的发现：反代 `$host` 会丢端口 ★
`nginx/kkfileview.conf` 原写 `X-Base-Url $scheme://$host/kkfileview`，实测对外端口 8090 时
生成 `baseUrl = 'http://127.0.0.1/kkfileview/'` —— **端口丢失**，浏览器会去请求 80 端口 → **iframe 白屏**，
而服务端日志全 200、健康检查正常、反代无报错，极具迷惑性。

- 根因：nginx `$host` **不含端口**，`$http_host` 才含。
- **修复：改用 `$http_host`**（`X-Base-Url`、`Host`、`X-Forwarded-Host` 三处都改）。
- 修复后 `baseUrl = 'http://127.0.0.1:8090/kkfileview/'` ✓
- **只有对外端口非 80/443 时才会暴露**，所以 80 端口下测正常不代表没问题。
- 自检命令：`curl -s ".../onlinePreview?url=<b64>" | grep -oE "baseUrl = '[^']*'"`

### 端口冲突
`.env` 原默认 `NGINX_HOST_PORT=8080` **撞上既有服务 `maple-cloud`**（已改默认 **8090**）。
本机占用：8080=maple-cloud、8081=maple-cad-viewer、8082=maple-onlyoffice、8088=jmalcloud、5678=n8n。
**教训**：端口被占时 compose 会报 `Bind failed: port is already allocated`，但若该端口上本来
就有别的服务在响应，自检脚本会**误判成"反代已就绪"**，测出来的是别人的服务 —— 必须先确认容器真的起来了。

## 续三：多格式文件加载实测（7 种格式 × 直连/反代）

**结论：全部通过。** 覆盖 txt/pdf/docx/png/html/csv/md，`previewType` 分别映射为
SIMTEXT / PDF / OFFICE / PICTURE / CODE / OFFICE / MARKDOWN。

| 格式 | previewType | 验证方式 |
|---|---|---|
| .txt | SIMTEXT | 页面内联渲染 |
| .pdf | PDF | 经 `getCorsFile` 取流 → 文件头 `%PDF-1.4` |
| .docx | OFFICE | 转换产物 `%PDF-`、17392 字节、HTTP 200 |
| .png | PICTURE | 页面内联 `<img>` |
| .html | CODE | 页面内联渲染 |
| .csv | OFFICE | 经 `getCorsFile` 取流 → 200 |
| .md | MARKDOWN | 页面内联渲染 |

服务端指标：`文件转换成功` 2 次、`exit code 134` **0** 次、`ERROR` **0** 次。

### ★ 重要机制：`getCorsFile` 代理（跨域文件源的标准路径）★
`pdf.ftl` / `csv.ftl` 等模板里有这段设计：

```js
var url = '${finalUrl}';                              // 源文件地址
if (kkagent === 'true' || !url.startsWith(baseUrl)) {  // 不以 baseUrl 开头 → 判定跨域
    url = baseUrl + 'getCorsFile?urlPath=' + encodeURIComponent(Base64.encode(url)) + "&key=...";
}
var viewerUrl = baseUrl + "pdfjs/web/viewer.html?file=" + encodeURIComponent(url);
```

所以**页面里 `var url` 出现源地址（如 `http://kk-testfiles/test.pdf`）是正常的**，
浏览器会执行 JS 走代理。**用 curl 直接请求这个原始值必然失败（HTTP 000）** ——
自检时必须手动复现这段逻辑：`getCorsFile?urlPath=<Base64(url)>`。

### ★ 两个曾误判为缺陷的假警报（写自检脚本时注意）★
1. **`Base64解码失败`**：这是 SIMTEXT 模板 `try/catch` 里的 `console.error` 文案，
   **永久存在于页面源码**。用 `grep` 扫全文必然命中 → 误报。
   判定错误要用「上下文定位」或检查页面是否含真实渲染容器，不能只看关键词。
2. **HTTP 000**：见上一条，是拿未执行 JS 的原始 url 去 curl 导致的。
   `000` 是 curl 的连接失败码，**不是 HTTP 状态码**，别与 404 混淆。

### ★ 运维经验：清理产物目录后必须重启容器 ★
测试中删掉 `data/file/*` 后，docx 预览返回 200 但产物 404，**日志里没有任何转换记录**。
原因：kkFileView 依据产物文件名做**转换缓存判定**，缓存（`KK_CACHE_TYPE=jdk` 为内存）
记住"已转换过"→ 跳过转换直接返回页面 → 页面引用的 PDF 不存在 → **iframe 白屏**。

**正确做法**：清理 `data/file/` 后必须 `docker restart kkfileview`（或 `--force-recreate`），
不能只删文件。排查此类问题时，**关键判据是日志里有没有 `Executing local conversion task`**。

## NebulaDisk 云盘（kkFileView 单镜像合并方案）—— 测试链路修复

### ★ 血泪教训：curl on Git Bash 有两个致命坑，测试一律改用 Python ★
本机 `curl 8.21.0 (Windows)` 在 Git Bash 下：
1. **不把 `HttpOnly` cookie 写进 jar**。服务端 `set-cookie` 完全正常
   （`nebula_session=...; HttpOnly; Max-Age=43200; Path=/; SameSite=lax`），
   但 `curl -c` 写出的 jar **0 行数据**。后果：登录后的所有请求 401，
   **看起来像云盘鉴权彻底坏了**，极难定位。
2. **`/tmp` 映射到 Windows 路径**，`curl -o /tmp/x` 写不出来 → 状态码 `000`。

**结论**：凡涉及「登录 + 保持会话」的测试，不要用 bash + curl，
统一用 managed Python + `httpx.Client`（cookie 自动管理）。
已落地：`tools/e2e_api.py`（58 项）、`tools/e2e_preview.py`（25 项），
`e2e-api.sh` / `e2e-preview.sh` 退化为只负责找 python 的薄封装。

### ★ 修掉的真 bug ★
1. **会话密钥每次启动都重新随机**（`config.py`）：
   原实现每次进程启动 `secrets.token_urlsafe(48)`，导致
   (a) 任何第二个进程（CLI/worker/测试）签的 token 主服务验不过，表现为满屏 401；
   (b) 容器重启 = 全员掉线。
   **改为生成一次并持久化到 `$NEBULA_DATA_DIR/secret.key`（0600，O_EXCL 防并发写）**，
   多进程/重启共用同一把。写入失败退回进程内临时值，保证服务仍能起。
   另修：数据目录为相对路径时 `resolve()` 成绝对路径，免把 `secret.key`
   散落到 CWD（Windows 上 `/var/lib/nebula` 会被当相对路径）。
2. **`/api/preview` 不拦目录**（`main.py`）：漏了 `p.is_dir()` 判断，
   目录也能拿到预览地址。`/api/oo/config` 有该判断，`/api/preview` 没有。
   已补 `if p.is_dir(): raise HTTPException(400, "目录不支持预览")`。
   （注：`/api/raw` 与 `/api/download` 走 `_stream_file`，其内部已有
   `if not p.is_file(): 404`，无需重复。）

## 第二轮：容器实机联调（镜像 nebula:1.0.0，宿主机端口 8089）

### 镜像已构建成功并可部署
`nebula:1.0.0`，3.8GB，`FROM kkfileview:5.0.2`。PID 1 = supervisord，
三个子进程 RUNNING：`kkfileview`(java) / `nebula`(uvicorn) / `exitmon`。
容器在 `deploy_default`(172.19.0.5) + `nebula_default` 两个网络里。

### P1（已修）：镜像里烧的是旧 supervisord.conf，不是 supervisord 的坑
之前那个 `[eventlistener:exitmon] section sets redirect_stderr=true` 报错，
**根本不是 supervisord 的解析问题**，是我改了宿主机文件（105 行）但**没重建镜像**，
镜像里还是旧的 92 行版本（第 92 行真有 `redirect_stderr=true`）。

教训：**配置改了没生效，先怀疑镜像没重建，不要去看解析器源码。**
当时我甚至去读 `options.py` 的 `process_groups_from_parser` / `saneget` 想找
「跨 section 继承」的机制 —— 其实 `saneget` 只回退到默认值（`'false'`），
不存在继承。一个 `sed -n` 看镜像内文件就把问题解决了。

正确姿势：
```bash
docker run --rm --entrypoint /bin/sh nebula:1.0.0 -c \
  'grep -n "redirect_stderr" /etc/supervisor/conf.d/nebula.conf'
```
然后**重建镜像 + `--force-recreate`**（只 recreate 不够，必须重建）。

### P2（已修，重要）：raw 直链缺扩展名 → 所有预览全挂
现象：kkFileView 对**每个文件**都返回同一个 1091 字节的 HTML 错误页
（"系统还不支持该格式文件的在线预览"），但 HTTP 状态码是 **200**。

根因：kkFileView 判类型靠 `url` 字符串里最后一个 `.`。原 raw 链接是
`/api/raw?mount=..&path=/readme.md&exp=1789882982&sig=..`，`lastIndexOf(".")`
命中的是 `exp` 的小数点 → `StringIndexOutOfBoundsException: Range [0, -1)`。

修法：文件名放进**路径** → `/api/raw/{filename}?mount=..&exp=..&sig=..`
（`make_raw_url` + `@app.get("/api/raw/{filename}")`；文件名只用于取后缀，
不参与鉴权）。改完各文件响应大小终于不同：md 12521B / png 4682B /
pdf 4446B / csv 4432B / txt 4710B，且 title 分别是对的
`文本预览`/`图片预览`/`PDF预览`/`csv预览`/`普通文本预览`。

### P3（已修，重要）：NEBULA_BASE_URL 没配，OnlyOffice 拉不到文档
`_internal_origin()` 原本硬回退到 `http://127.0.0.1:8088`。但 OnlyOffice 在
**另一个容器**里，它的 127.0.0.1 是它自己 → 永远拉不到。
已在 compose 设 `NEBULA_BASE_URL: "${NB_BASE_URL:-http://nebula:8088}"`，
并在 `_internal_origin()` 里加了显式告警日志。

验证（关键）：用 **OnlyOffice 容器自己**去 curl：
```
HTTP 200  size=1146  type=application/vnd.openxmlformats-...wordprocessingml.document
00000000: 504b            ← "PK"，是合法 docx
```

hash 从 b6731266… 变成 bd1f97db…，1146→972 字节，解压能读到新文本。

### ★ P4（已修，阻塞级）：#boot 被移除后无判空访问 .style，异常被误报成「登录失败」★
**现象**：正确用户名密码登录，界面红字提示
`Cannot read properties of null (reading 'style')`，**永远停在登录页**。
但**服务端返回 HTTP 200 且 `{"ok":true,"username":"admin",...}`** —— 认证其实成功了。

**因果链**（每一步都单独验证过）：
1. 页面加载 → `API.me()` 401 → `showLogin()`；
2. `DOMContentLoaded` 里第 41-44 行把启动遮罩 `#boot` **`remove()`** 掉（延时 400ms）；
3. 用户登录 → `enterDesktop()` → `ViewerBoot.setWallpaper()` 第 511 行
   `document.getElementById('boot').style.background = bg` → 元素已不存在 → **TypeError**；
4. 该 TypeError 从 `enterDesktop()` 冒泡，被登录的 `try/catch` 捕获 →
   `errEl.textContent = err.message` → **把内部异常当成"登录失败"展示**。

**极其隐蔽之处**：`setWallpaper()` 里第 508、510 行都有判空（`if (ls)`），
**只有第 511 行漏了** —— 三行同构代码，两行安全一行不安全，肉眼扫代码极易放过。

**两处修复**：
1. `setWallpaper()` 第 511 行加判空（`const boot = ...; if (boot)`），并写注释说明为什么。
2. **`showLogin()` 拆分 try 块**：`API.login()` 单独一个 try（只它失败才算认证失败），
   `API.me()` + `enterDesktop()` 移到**另一个** try/catch（失败提示"登录成功但桌面初始化失败"，
   并 `console.error` 打堆栈）。**根因是错误归因，不只是那一个空指针。**
   不这样改的话，以后 enterDesktop 里任何 UI 异常都会再次被伪装成"密码错"。

### ★ 浏览器实测方法论（本机 agent-browser 的两个陷阱）★
- **`agent-browser eval` 每次调用都是新的页面上下文**，跨调用不保留页面状态。
  表现：连续 eval/`snapshot` 结果自相矛盾（一次 body 5903 字符、下一次 0；
  一次能查到 input、下一次查不到）。`--session <name>` 也没能钉住页面。
  → **多步交互（填表→提交→读结果）必须写成一个自包含的 async 脚本，
     用 `agent-browser eval --stdin < script.js` 一次执行完。**
- **`screenshot` 会拍到最后一次导航后的空白页**：曾拍出纯黑 PNG
  （3680 字节），误判为"页面渲染失败"。加**缓存破坏参数** `?t=$(date +%s)`
  重新 open 后即正常，截图 32684 字节，登录页像素级正确。
  → 判定"渲染坏了"之前，先确认拍的是当前页面，别拍空白标签页。
- `snapshot -i` 对这套 UI 返回 `(no interactive elements)`，但 `querySelectorAll`
  能查到（`lg-user` / `lg-pass` / `start-search-input`），说明 snapshot 的可见性
  判定不适用于这种自绘桌面 UI。**以 DOM 查询为准，别信 snapshot 的空结果。**

### ★ P5（已修，阻塞级）：imgUrl 读 state.cur 早于其赋值 → 目录永久「正在加载…」★
**现象**：登录进桌面后，文件列表**永远停在「正在加载…」转圈**，刷新也没用，
没有报错弹窗、没有重试按钮。

**根因（有完整堆栈）**：
```
TypeError: Cannot read properties of undefined (reading 'mount')
    at imgUrl (explorer.js:472)      ← const S = state.cur; 此时 undefined
    at tileImg (explorer.js:464)
    at renderGrid (explorer.js:449)
    at renderFiles (explorer.js:406)
    at load (explorer.js:315)
```
`renderGrid()` 先拼 `innerHTML`（内部调 `tileImg` → `imgUrl`），**拼完才调 `bindTiles()`**，
而 `state.cur = S` 恰恰写在 `bindTiles()` 里 → **首次渲染时 `state.cur` 还是 undefined**。
`renderGrid` 明明有 `S` 参数，`tileImg`/`imgUrl` 却绕过它去读全局。

**放大器**：`load()` 里只有 `API.list()` 被 try 包住，渲染段在外面。
异常穿出后，开头已置的 `S.loading = true` **永远不会复位**，
后续所有刷新都被 `if (S.loading) return` 静默吞掉 → 永久卡死。

**两处修复**：
1. `imgUrl(e, S)` / `tileImg(e, S)` / `listThumb(e, S)` 全部改为**由调用方透传 S**，
   `imgUrl` 里再留 `S = S || state.cur` 兜底 + `if (!S) return ''`，
   保证缩略图()任何情况下都不会把整个列表搞崩。三处调用点全部补上 `S`
   （renderGrid / renderList 表格 / 详细信息面板）。
2. `load()` 重构为 **单个 try/catch/finally**：渲染也纳入 try，
   `S.loading = false` 挪到 `finally`。**任何异常都不再能造成永久 loading。**

### ★ P6（已修，DWG 打不开的根因）：`_origin()` 误用了给容器用的 BASE_URL ★
**现象**：双击 `.dwg`，预览窗口打开但**永远停在「正在加载SVG...」**，
有缩放按钮和"100%"提示，就是不出图。

**排查过程（值得复用）**：
1. 看容器日志：请求确实进来了（`previewType：CAD`），
   且每 ~7 秒重试一次 —— 那是等待页在轮询，说明前端认为"还没转好"。
2. **关键否定证据**：日志里 **完全没有 CAD 转换的成/败记录**。
   对比 docx 有 `文件转换成功：... 耗时：406毫秒`。
   （一度据此怀疑转换根本没跑。）
3. 直接查产物目录：**`立库规划图块dwg.svg` 存在，7,890,188 字节** ——
   **转换其实成功了**，之前的怀疑被推翻。
4. 把预览页 HTML 抓下来看，命中三行要命的东西：
   ```js
   var url     = 'http://nebula:8088/preview/立库规划图块dwg.svg'
   var baseUrl = 'http://nebula:8088/preview/'
   ```
   **`nebula` 是 docker 网络里的名字，浏览器根本解析不了。**
5. 做对照实验：把同一 URL 的 `nebula:8088` 换成 `127.0.0.1:8089` →
   **200 + `image/svg+xml` + 7890188 字节**。**根因确认。**

**根因**：`main.py` 的 `_origin()`（拼发给**浏览器**的 `X-Base-Url`）里写了
```python
if settings.base_url:      # = NEBULA_BASE_URL = http://nebula:8088
    return settings.base_url
```
但 `NEBULA_BASE_URL` 是给**容器内其它服务**（OnlyOffice 回拉、kkFileView 同容器访问）
用的，取的是容器名。**两个不同消费者共用一个变量** → 浏览器拿到内网主机名。

kkFileView 的 `BaseUrlFilter` 优先级：`X-Base-Url` 头 > 配置 `base.url` > 按请求拼。
所以注入的头一旦是 `nebula:8088`，页面里所有资源地址全变成不可达内网地址。

**修复**：`_origin()` **去掉 `base_url` 分支**，一律从**本次真实请求**的
`X-Forwarded-Host` / `Host` 推导 —— 它天然就是浏览器用的那个地址（含端口）。
`_internal_origin()`（给 OnlyOffice 的）**保持使用 `base_url` 不变**。

**教训（可迁移）**：「同一个地址变量服务于浏览器和容器两种视角」是高频坑。
凡是拼给浏览器的绝对地址，**只能来自请求本身**，不能来自为容器准备的配置。

**注意**：DWG 的 SVG 产物走 `/preview/xxx.svg`（kkFileView 内置静态映射），
不是 `/file/xxx.svg`（后者 404）。反代前缀是对的，别改错方向。

### 三、需求 C：STEP 模型「No importable file found」——**两个独立 bug**
用户怀疑「传入的路径或内容不对」，查官方 FAQ 后确认**内容没问题，是名字被截断了**。

**★ 官方依据（3dviewer.net/info/faq.html）★**
> Online 3D Viewer tries to detect importable files by extension.

即 o3dv **纯按扩展名**判断可导入性。三条报错含义不同：
`No importable file found` = 扩展名不认/没有；
`Failed to import model` = 扩展名认了但内容解析失败；
`Failed to load occt-import-js` = WASM 导入器没加载起来。
支持列表：`3dm 3ds 3mf amf bim brep dae fbx fcstd gltf ifc iges step stl obj off ply wrl`
—— **dwg/dxf 不在其中**（那是 cad-viewer 的地盘）。

**★ 首先要认清：这是哪个查看器 ★**
截图里三栏 UI（左 Meshes 树 / 中 3D 视口 / 右 Details 显示 Vertices·Triangles·Unit·Size）
是 **Online 3D Viewer (o3dv)**，它**内置在 kkFileView 自己的 jar 里**：
`src/server/src/main/resources/static/website/`，入口
`FileType.ONLINE3D("online3DFilePreviewImpl")` → 模板 `online3D.ftl`。
与 cad-viewer（渲染 dwg/dxf、界面完全不同）是两套东西，别混。

**bug 1：文件名里的 `#` 截断 fragment → 扩展名丢失**
- 现场：`1.2.14.TFDF-6# F向.STEP`。上游 `online3D.ftl` 原文是
  `...index.html#model="+ url + "&fullfilename=/${file.name}"`，
  文件名**原样**拼在 `#` 后面。文件名自带 `#` → 浏览器把它当 fragment 分隔符，
  其后内容（含 `.STEP`）全被截掉。
- 证链：解析 iframe 的 hash 得 `fullfilename=/1.2.14.TFDF-6`，
  推出扩展名 **`tfdf-6`**（非法）；同一时刻 `modelFetch` 返回
  **200 / 3,709,570 字节 / 开头 `ISO-10303-21;`** —— 一份完全合法的 STEP。
  **内容无辜，只有名字被毁。**
- 修复（`nebula/overrides/web/online3D.ftl`）：
  1. 文件名走 `encodeURIComponent` 再拼进 fragment（o3dv 用
     `URLSearchParams(location.hash.substring(1))` 读取 → 会自动解码，编码是正解）；
  2. 所有 Freemarker 插值改用 `${x?js_string}` —— 原写法 `${file.name}` 直接塞进
     单引号 JS 字符串，文件名带单引号会**提前闭合脚本**导致整页白屏。
- 修后：`fullfilename="/1.2.14.TFDF-6# F向.STEP"`、扩展名 `step`、错误文案为空。

**bug 2：o3dv 把资源路径写死在站点根 → 404**
- 修完 bug 1 后报错变成 `Failed to import model / Failed to load occt-import-js`。
- 证链：`/website/libs/occt-import-js-worker.js` → **404**；
  `/preview/website/libs/...` → **200**。o3dv bundle 里硬编码
  `let baseUrl = window.location.origin; let n = baseUrl + "/website/libs/";`，
  它假设自己被挂在站点根 `/`，而我们在反代前缀 `/preview/` 下。
- 修复：`nebula/app/main.py` 加 `/website/{rest:path}` 别名路由，
  把根路径的 `/website/*` 转给 kkFileView 的 `/preview/website/*`
  （声明在 604 行、catch-all `/` 之前，与 `/static` 不冲突）。
- 修后：三个资源（`occt-import-js.js`、`.wasm` 带 `application/wasm`、
  `occt-import-js-worker.js`）在根路径全部 200。

**最终验收**：STEP 模型完整渲染 ——
`Vertices: 27,999 / Triangles: 29,942 / Unit: Millimeter /
Size X: 1,055.00 · Y: 962.00 · Z: 1,337.32`，`canvasCount:1`。

### ★ 模板覆盖机制（本会话复用，值得记牢）★

  让 Git Bash 与 WSL 两种进入方式各自得到自洽的路径。

- **教训**：`pwd -W`、`$(... || fallback)` 这类「静默兜底」在跨 shell 场景极其危险 ——
  兜底值本身是错的（Windows 字面量），但流程不会报错，一路走到最后一步才炸。

### 1. 双击文件夹不打开文件夹窗口（用户原文：
「双击文件夹，不会打开文件夹窗口，需要修复。」）

**根因**：`Explorer.open()` 的窗口 id 是 `explorer:${mount}` —— **一个映射只对应
一个窗口**。双击文件夹走 `activate()` → `navigate()`，而 `navigate()` 是
**在当前窗口内原地换目录**，不会新建窗口。用户预期「打开一个文件夹窗口」，
看到没有新窗口出现，就判定为「没反应」。

**修法**（`nebula/web/js/explorer.js`）：
- `open()` 新增 `opts.newWindow`：为 true 时窗口 id 改为
  `explorer:${mount}:${path}`，实现「一个目录一个窗口」。
- 新增 `openChild(body,S,name)`，`activate()` 对文件夹改调它。
- 新增 `baseName(p)` 取路径末段，窗口标题用文件夹名（否则多开时全同名）。
- **`winIdOf(S)` 从 `explorer:${S.mount}` 改为返回 `S.winId`** ——
  这是关键点：id 变了之后，若 `winIdOf` 仍按 mount 拼，
  `WM.get()` 会返回 undefined，导致**标题不更新 + 键盘快捷键整套失效**
  （`bindKeys` 里 `if (!st) return`）+ navigate 渲染到旧节点。

**顺带修掉一个继承下来的语法错误**：
`renderShell` 的模板字面量里有一处 **未转义的反引号**
（`WM._bindDrag 内部已经 \`if (...)\`` 这句写在 HTML 注释里，但注释在
**模板字符串内部**，反引号会提前结束字符串）。
`node --check explorer.js` 直接报 `SyntaxError: Unexpected token 'if'`。
已改为 `\``。**注意：这个错误在改动前就已存在于已部署版本里。**

### 2. OnlyOffice / kkFileView / CAD 窗口点击不置顶（用户原文：
「如果弹出的是onlyoffice或者kkfileview或者cad的窗口，
那么点击窗口不会对窗口做弹最前，需要修复」）

**根因**：这三类预览窗口的内容都是 `<iframe>`。
**点击 iframe 内部时事件不会冒泡到父文档**，所以
`el.addEventListener('mousedown', () => focus(id), true)` 收不到，
`focus(id)` 不执行 → 永不置顶。（自己渲染 DOM 的窗口没这问题，
所以症状只出现在这三种窗口上。）

**修法**（`nebula/web/js/shell.js`）：新增 `_bindIframeFocus(state)`，三条路径：
1. **同源 iframe**：`fr.contentWindow.addEventListener('focus'/'mousedown')`
   → `focus(id)`。本应用预览都走同源反代 `/preview/`，所以可用。
2. **兜底**：`fr.addEventListener('focus', ...)`（父文档 activeElement 变 iframe）。
3. **全局兜底**：`document` 上挂 `focusin`，若 target 是本窗口的 iframe → 置顶。
   `close()` 时由 `_unbindIframeFocus(state)` 摘除（否则会攒野指针）。
跨域时 `contentWindow` 访问抛错 → `try/catch` 静默降级。

### 3. 压缩包内文件预览报 CORS（用户原文：
「在压缩文件里面预览文件，预览不了，报错：
 The remote server refused to fulfill the request. (CORS request failed.)」）

**复现到的两条真实报错**（`docker logs nebula`）：
```
(1) ResourceAccessException: I/O error on GET request for
    "http://127.0.0.1:8089/preview/00-Q3-1250.zip_/00-Q3-1250.stp":
    Connect to http://127.0.0.1:8089 failed: Connection refused
(2) URISyntaxException: Illegal character in fragment at index 44:
    http://127.0.0.1:8089/preview/1.2.14.TFDF-6# F向.zip_/1.2.14.TFDF-6# F向.STEP?...
```

**根因 (1)**：`compress.ftl` 用 `${baseUrl}` 拼压缩包成员地址，
而 kkFileView 拿到后是**在服务端**去 GET 的（`getCorsFile`）。
`${baseUrl}` 来自网关注入的 `X-Base-Url` = 「浏览器源 + /preview」
（如 `http://127.0.0.1:8089/preview`）。这是**容器内**进程，
里面 `127.0.0.1:8089` 根本没人监听（8089 只是宿主机端口映射）。
对照实验：容器内 `127.0.0.1:8089/healthz` → 000 拒绝；
`nebula:8088/healthz` → 200。

**根因 (2)**：`'${baseUrl}' + treeNode.id` 是**原样拼接**，
压缩包名含 `#`（`1.2.14.TFDF-6# F向.zip`）时 `#` 被当作 fragment 起点，
Java URI 解析直接抛异常。

**修法（两处配合）**：
- **模板侧**（`nebula/overrides/web/compress.ftl`）：

## 【重大教训】压缩包"自愈"逻辑反而冻死整站 — 已整体移除

**用户报告**：预览压缩包时，整个系统变得非常慢，各个服务变成「检查中」。

**根因（自查确认，是上一轮自己引入的回归）**：
网关 `nebula/app/main.py` 里曾有一个 `_heal_compress_member`，用来修 kkFileView
的「缓存说已解压、磁盘目录却没了」→ 成员 404 的边角问题。它是**同步阻塞**
函数，却直接被放在 `proxy_preview` 的**响应路径**上，内部两次同步 httpx：
  - `/directory` 探测           最长 15s
  - 强制重解压 `/onlinePreview` 最长 300s

而这个网关是**单 worker 的 uvicorn**（supervisord 启动参数没有 `--workers`）。
所以一次 48MB `.stp` 的解压（几十秒）就把唯一的事件循环占死：
  - 前端所有请求排队 → 整站转圈变慢
  - `/healthz` 是**纯内存**接口也被卡住 → docker 健康检查超时
    → 容器判 unhealthy → 用户看到「各个服务变成检查中」

**决策：整体删除，不打补丁。** 理由：
  1. 收益（一个缓存错位场景）远小于风险（单点冻结全站）
  2. 该缺陷属 kkFileView 自身，部署侧解决更合适
     （启动时清解压产物目录 / 换外部缓存 redis / 给 uvicorn 加 workers）
  3. 用户明确判断「这个自愈本身就是问题来源」，事实确实如此

**保留的真实修复**（这些才是「一个能、一个不能」的正解，务必留住）：
  - `compress.ftl` 的 `__SERVER_BASE_URL__` 占位符 + 网关侧替换
    ⇒ 服务端回拉用容器内可达地址，浏览器加载用浏览器源，两者拆开
  - query 里 `kkCompressfilepath`/`urlPath` 的 `#` → `%23` 兜底编码
    ⇒ 修文件名含 `#`（`1.2.14.TFDF-6# F向.zip`）导致的 URISyntaxException

**删除的东西**：`_heal_compress_member` / `_heal_compress_member_inner` /
`_schedule_heal_compress_member` / `_host_of`、去重用的 `_heal_lock` 等三件套、
`import threading`；以及依赖它们的测试 `_test_compress_heal.py`、
`_test_preview_nonblocking.py`。

**关键教训（写进 MEMORY.md）**：
  单 worker 的 ASGI 应用，响应路径上不许有任何阻塞 IO。
  慢接口会拖垮**整个**进程，包括 healthz —— 表现为"整机变慢 + 服务检查中"。
  看到 healthz（纯内存）都变慢，第一反应就该是"事件循环被占死"。

**顺带清理**：Docker build cache 曾涨到 25GB（248 条），已 `docker builder prune -af`
全部回收；`nebula/tools/_t/` 临时探针目录已删。

## 二次修复：热区死区 / 点击置顶 / 拖动不跟手（shell.js + app.css）

用户回头反馈 #1、#3 没修好，并新报一条。三件事都用 `elementFromPoint` 逐像素
实测定位，最终 74/74 断言全绿。

### ① 「调整窗口大小有 BUG」—— 热区周长有死区（真因，之前没找到）

用 `elementFromPoint` 沿窗口顶边逐点扫描，命中结果是
`win-body / win-body / win-body / DIV`，**顶边右侧约 110px 完全抓不到**。
两个叠加的错误：
  - `n` 条右端为给三键让位写成 `right: calc(14px + 113px)`，但**让出的那块
    没有别的热区接住** → 死区。
  - 四条边两端各留 6px 缝：让位用了**边厚** `s`(=EDGE=14)，而角是
    `CORNER=20`，20−14=6 → 每条边两端 6px 落空。

**改法**：按两条独立规则重新拼装周长 ——
  · 边厚一律 `EDGE`，边两端让位一律 `CORNER`
  · 四个角一律 `CORNER × CORNER` 贴各自的角
  · `n` 条右端**紧贴** `ne` 角（不再为三键挖空；三键靠 CSS `z-index:950`
    压在热区 900 之上来保证「关闭」优先命中）
于是「角＋边＋角」首尾相接，整条周长零缝隙。

### ② 「点击窗口内部不能置顶」—— 重叠窗口被一起抬起

`_bindIframeFocus` 的几何兜底是**每个窗口一个 `document` mousedown 监听**。
两个 iframe 窗口 A/B 重叠（B 在上）时，点 A 的 iframe 内部会触发**两个**监听，
两个都调 `focus()`，后处理的 B 拿到更大的 zTop → **B 留在上面，A 永远上不来**。
实测：`{zA:102, zB:104, zA_after:105, zB_after:106, Araised:false}`。

**改法**：加 `_winOfNode(node)`（沿 parentNode 找 `dataset.winId`）+
`elementFromPoint` 判定「这一点归谁」：
  - 归属别的窗口 → 不抢
  - 归属不到 → 退回「本窗口是否是该点 z 序最高者」比较

### ③ 「窗口拖动的位置有时不能跟随鼠标位置」—— iframe 吞指针事件

根因：预览/编辑窗口的 body 被 iframe 铺满。拖动时窗口跟手有 1 帧延迟，
快速拖 / 往下拖时指针会先落到 iframe 上方，而**指针一旦进入嵌套浏览上下文，
父文档的 mousemove 就不再触发** → 拖动**永久卡死**；更糟的是 mouseup 也丢，
`dragging` 一直是 true，之后鼠标扫过窗口就把窗口瞬移过去。
「有时」= 只在指针越过 iframe 时发生。

**改法（两道保险，各自都能独立解决）**：
  1. **整屏透明遮罩** `.wm-drag-shield`（`position:fixed;inset:0;z-index:9998`），
     拖动/缩放期间挂在 `document.body`。它盖在所有 iframe 之上，指针永远
     落在它上面 → 父文档事件永不丢失。顺带解决拖动时选蓝文字、光标跳箭头。
  2. **指针捕获** `bar.setPointerCapture(e.pointerId)`。规范保证被捕获元素
     收到**全部**指针事件，与指针位置无关。
另外把手势从 `mousedown/mousemove` 全面换成 `pointerdown/pointermove/pointerup`
（+ `pointercancel` / `lostpointercapture` 兜底），收尾函数挂到 `state._dragUp`
/`state._resizeUp`，`close()` 里兜底撤除遮罩（防止拖到一半关窗把遮罩留在屏上）。

### 附带修正

- 几何起点从 `state.el.offsetLeft`（**取整**、offsetParent 相对）改为

### 扫描器自身的两个误判（写扫描脚本时注意）

### 二、首跑 24/3 失败 —— 三个都是**桩的保真度问题**，不是产品 bug

1. **`appendChild` 只设了 `parent`，没设 `parentNode`。**

2. **手搓的 marker 元素没设 rect。** `elementFromPoint` 桩按矩形命中，

### 三、★ 纯逻辑测试全绿 ≠ 真实浏览器对 ★ —— 这是本轮最大的教训

## 2026-09-20（续）/ 09-21 —— 两个新需求：①同类翻页 ②点窗口任意位置置顶

用户原文：
> 照片预览 上面的总数目前是所有文件的总数，但是切换时 到别的类型文件时，
> 提示无法显示这张照片。而不是调用其他程序打开该文件。
> 编辑和预览文件的窗口 目前还没有实现 点击窗口任何地方就聚焦成最前端显示。

### 需求 ①：翻页只在**同类型**内（viewer.js）

**根因**：翻页列表原来只排除文件夹/隐藏文件，是「全部可预览文件」。
看照片时按 next 会走进 .csv / .py，交给 `<img>` 就是「无法显示这张照片」。

**修法** — `viewer.js`：
- 新增 `kindOf(entry, path)` → `'image'|'video'|'audio'|'text'|'cad'|'onlyoffice'|'kkfileview'|null`。
  **判定顺序必须与 `open()` 的路由优先级一致**：`route==='cad'` → `route==='onlyoffice'`
  → `nativeKind(ext)`（image/video/audio/text）→ `route==='kkfileview'` → `null`（只能下载）。
- 新增 `siblingsOfKind(entries, kind)` = `previewableList(entries).filter(e => kindOf(e) === kind)`。
- `makeCtx` 算 `kind` 并用 `siblingsOfKind(all, kind)` 收窄列表；ctx 增加 `kind` 字段。
- `refreshContext` 用 `c.kind ? siblingsOfKind(entries, c.kind) : previewableList(entries)`
  —— **目录一刷新不能退回宽列表**。
- `step()` 加最后一道防线：`if (c.kind && kindOf(e) !== c.kind) return false;`
- `kindOf` 加进导出对象（供测试/调试）。
- 图片 `error` 处理器改为给出真实出路：「在新标签打开」「下载到本地」，
  而不是只丢一句「无法显示这张照片」。

### 需求 ②：点 iframe 预览窗口**任意位置**都置顶（shell.js）

**根因（前三条路径全依赖「焦点转移」）**：
OnlyOffice / CAD / kkFileView 的内容都是 `<iframe>`。点在 iframe 内部时事件被
iframe 自己的浏览上下文吃掉，父文档收不到。于是：
- 第 1 次点 → focus 转移 → 置顶（用户看到的「点中间才行」）
- 第 2 次起 → `activeElement` 没变，浏览器**不再派发** `focus`/`focusin` → 毫无反应
- 旧的「几何兜底」在父文档听 `mousedown`，同样收不到 iframe 内部点击；
  而且**每个窗口各挂一个 document 监听**，重叠时会互相抢着置顶（A 被点却被 B 压住）

**修法（标准做法，与是否同源/跨域全无关）**：在 iframe 上盖一层**透明点击盾**
`.iframe-shield`（`position:absolute; inset:0; z-index:5; pointer-events:auto`）。
它属于父文档 → 它的 `mousedown` 必定冒泡到窗口 `el` 的捕获监听 → `focus(id)`。
- 非最顶层 → 盾生效（`pointer-events:auto`）
- 置顶后 → 立刻 `pointer-events:none`，内容立即可交互
- 别的窗口一上来 → `focus()` 里的 `_syncAllShields()` 重算 → 盾重新生效
- 盾的 sync 回调挂在**模块级 `Set`（`_shieldSyncHooks`）**上，不再每窗口一个
  document 监听；`_unbindIframeFocus` 里摘盾 + 注销回调。

**★ 本次被测试抓出的真 bug（TDZ）**：`attach()` 原本在 `makeShield`/`syncShield`
（const 箭头函数）**之前**调用 →
`ReferenceError: Cannot access 'makeShield' before initialization`，
会让**每个** iframe 预览窗口打开即崩。已把 `attach()` + MutationObserver 移到
所有依赖定义之后。
