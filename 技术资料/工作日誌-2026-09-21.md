## 1. resize 热区：三轮用户反馈收敛

用户反馈演进（很重要，记录了取舍方向，别再走回头路）：
1. 早期：「调整大小需要按住才能调整」→ 热区太薄（5px）按不准 → 加宽到 **14/20**
2. 本轮：「感应范围感觉太快了，同时是不是可以增加一下 延时显示。」
   → 问题从"太薄"翻转成"太宽太快"
3. 本轮澄清：「感应范围太宽也太快。」「感应范围应该调整到窗口的边缘左右附近。」
   → 明确两件事：**几何要收窄** + **要延时** + **确认贴边缘**

### 1.1 几何收窄（EDGE 14→8，CORNER 20→12）

`shell.js` `_bindResize`：
```js
const EDGE = 8;       // 边热区厚度（14 → 8）
const CORNER = 12;    // 角热区边长（20 → 12）
```
- 仍 > 最初的 5px（保留下界，不重蹈"按不准"）
- 角仍 > 边（斜向缩放捕获区更大）
- **让位规则不变**：边让位用 CORNER、四角 CORNER×CORNER —— 这才是周长零缝隙的保证
  （若让位误用 EDGE，角与边之间会露 CORNER-EDGE 的空档 → 抓不到）

### 1.2 延时显示（hover intent）—— 本次核心新机制

新增常量 `RESIZE_HOVER_DELAY = 380`（用户说"太快"，从 260 提到 380）。

机制（`_bindResize` 内，每个窗口一份 `hover` 状态）：
| 事件 | 行为 |
|---|---|
| `pointerenter` | `clearHover()` → 起 380ms 定时器 |
| 定时器到期 | 若热区还在且窗口未最大化 → `armDir(dir)` |
| `pointerleave` | `clearHover()` + 光标回落 `default` |
| 热区内 `pointermove` | **不重置**定时器（否则手抖永远等不满） |
| 换到别的方向热区 | 先撤销旧定时器再重新计时 |
| `pointerdown` | **无条件** `armDir(dir)`，不等延时 |

`armDir(dir)` 做三件事：`el.style.cursor = '<dir>-resize'`、
`el.dataset.armed = '1'`、`document.body.style.cursor = '<dir>-resize'`。

**关键设计取舍：延时只作用于"光标提示"，绝不延迟真正的拖拽。**
急着拖的用户体感零延迟，只是不会在半路被光标闪到。

配套改动：
- 热区 inline `cursor` 从 `` `${dir}-resize` `` 改为 `'default'`
- CSS 加 `[data-resize] { cursor: default; }` 兜底（JS 未跑时不退化成旧行为）
- `up()` 里 `resetCursors()` + `state._resizing = false`
- `close()` 里加 `w._resizeHoverClear()` 兜底清定时器

### 1.3 边缘定位实测（回答"应该调整到窗口的边缘附近"）

写了 `_hz2_probe.js` 用**直接读 `getBoundingClientRect()`** 的方式量热区
相对窗口边缘的位置（不靠 elementFromPoint 命中，避免被窗口遮挡干扰）。

真机实测结果（窗口 1100×550，border 1px，radius 8px）：
```
gap.e_right = -1    gap.w_left = 1     gap.n_top = 1     gap.s_bottom = -1
gap.ne_right = -1   gap.sw_left = 1    gap.sw_bottom = -1
gap.ne_top = 30   ← 故意：为右上角三键让位（--toolbar-h = 29px）
overflow = []     ← 无越界
eastScanHits = ",e,e,e,e,e,e,e,e,"  ← 从右沿往里连续 8px 命中 e 手柄
```
结论：**热区本来就精确贴在窗口边缘**（差值 ±1px 正是 1px 边框），
用户感知到的"偏内"很可能来自窗口圆角 / iframe 内容自带边距的视觉错觉。
本轮把厚度从 14 收到 8 后，边缘感会更明确。

## 5. Request D：热区**跨边框**（感应区伸出窗口外）

用户原文：
> 「调整窗口 鼠标感应 区域 以边框外边缘 向左和向右，向上向下偏移一定范围内
>   都可激活。目前都是在窗口里面，这个要调整一下。」

### 改动（`nebula/web/js/shell.js`）
- 新增 `const OUT = 4`（向**窗口外侧**延伸的像素数，`EDGE/CORNER` 仍是内侧厚度）。
- 两个助手：`OUT_N = -OUT + 'px'`（外沿偏移）、`span(len) = len + OUT + 'px'`（跨边框尺寸）。
- 8 个手柄全部改为 `left/right/top/bottom = OUT_N` + `width/height = span(...)`。
- ★★ 关键坑：`const CLEAR = CORNER + 'px'`（**不是** `CORNER + OUT`）★★
  角是 `right:-OUT; width:CORNER+OUT` → 它**向内只盖到** `win.right-CORNER`，
  外沿那 OUT 是往窗外去的。而 n/s 条的 `left/right` 量的是"从窗口内沿往内让多少"，
  只需让开角在窗内占的 CORNER。写成 `CORNER+OUT` 会空出 **OUT=4px 的缝**。
- ★ n 条右端改为 `right = OUT_N`（直达右沿外）★
  因为 ne 角纵向已下移到 `--toolbar-h`，与 n 条（y∈[-4,8]）**不重叠**，
  n 伸过去不抢 ne；代价是盖住三键顶部 12px，但三键 `z-index:950` 仍赢。

### 改动（`nebula/web/css/app.css`）

- 裁切职责下移：`.toolbar { border-radius: 上两角; overflow:hidden }`、
  `.win-body { border-radius: 下两角; overflow:hidden }`（视觉不变）。
- 新增 `.window.maximized [data-resize] { display: none }`（最大化时铺满视口，

## 6. 分享功能（Request E1）

用户诉求：「增加分享功能」。落地为**面向访客的 token 短链分享**。

### 数据层 `nebula/app/shares.py`（新）
- 表 `shares`：`token / owner / mount / path / name / is_dir / password /
  created_at / expires_at / max_visits / visits / note`，唯一索引 `idx_shares_owner`
- token = `secrets.token_urlsafe(24)`（32 字符）；**库里存明文 token**
  —— 刻意选择，因为 token 本身就是 URL 里的凭据，存哈希只会增加一次查表；
  安全性靠「32 字符不可枚举」+ 可随时撤销，不是靠不可逆
- 密码：可选，存 **bcrypt 哈希**（复用 `users.hash_password`）
- `ttl<=0` → `expires_at = 0` 表示永不过期（而不是 `now+0`）
- `revoke_under_path(owner, mount, path)`：`path = ? OR path LIKE pref+'/%'`
  —— 用 `pref + '/%'` 而不是 `pref + '%'`，否则 `/dir/a` 会误伤 `/dir/abc`

### 接口层 `nebula/app/main.py`
- 登录侧：`GET/POST /api/shares`、`/api/shares/revoke`、`/api/shares/update`
- 访客侧（**不挂 `current_user` 依赖**）：`GET /api/s/{token}`（返回 HTML）、
  `POST /api/s/{token}/unlock`、`GET /api/s/{token}/list`、
  `GET /api/s/{token}/raw`、`GET /api/s/{token}/preview`、
  `GET /api/s/{token}/sraw/{filename}`、`POST /api/s/{token}/oo-callback`
- 公开短链：`GET /s/{token}`

### 三个关键设计决定
1. **权限继承**：创建时用**创建者**的权限集校验 `(mount, path)`；
   访客访问时复用**分享者**作为可见性上下文（`_mount_for_share`），
   而不是按访客身份判断——访客可能根本没有账号。
2. **解锁凭据不是密码**：`POST /unlock` 成功后写 HttpOnly Cookie
   `nebula_share_<token[:16]>`，值 = `sha256(password_hash + token)`。
   即「解锁凭证」而非密码本身，泄露该 Cookie 也拿不到密码。
3. **给访客的 raw 链接必须自签名**：OnlyOffice / kkFileView 是**服务端**去
   GET 文档的，带不了访客的 Cookie。所以另发
   `/api/s/{token}/sraw/{filename}?token=&path=&exp=&sig=`，
   `sig = HMAC(jwt_secret, "share\n{token}\n{sub}\n{exp}")`。

### 穿越防护（双重）
访客给的 `path` 是**相对分享根**的子路径 → 先 `files.resolve()` 展开校验，
再 `_inside_share(m, p, sh)` 二次确认结果仍在分享根之内。

### 前端
- `web/share.html` + `web/css/share.css` + `web/js/share.js`：**独立自洽**的
  访客落地页（跟随 `prefers-color-scheme`），服务端把 `window.__SHARE__`
  注入到 `__SHARE_BOOT__` 占位符
- 云盘侧：`explorer.js` 加右键「分享」/「分享此文件夹」/「管理我的分享…」，
  新增 `icons.js` 的 `share:` 图标与 `api.js` 的四个封装

### 验证
- `nebula/tools/_test_shares.py`（新）：**48 通过 / 0 失败**，
  覆盖穿越拒绝（`../secret.txt` 等）、伪造 token、跨 owner 撤销被拒、
  owner 隔离、不泄露 password 字段、过期/超次、删除源文件→分享自动失效、
  前缀匹配不过宽（`/dir/abc` 不被 `/dir/a` 误伤）
- `selfcheck.py` 新增 `[9] 分享（安全边界）`（~24 条），路由清单扩到 **30 条**

## 7. 清理冗余 + 离线镜像包（Request E2/E3）

### 7.1 踩到的真坑：`nebula/.dockerignore` 一直是**失效**的
Docker 只读「上下文根」的 `.dockerignore`；想针对某个 Dockerfile 单独排除，
必须命名为 `<Dockerfile 名>.dockerignore` 并放在该 Dockerfile **同目录**。
原名 `nebula/.dockerignore` 名字不对 → daemon 根本不读 →
每次 `docker build` 都把 `sample/`(219MB)、`docs/`、`tools/`、`nebula/.env`
一起打包传给 daemon（慢，且把本地密钥带进构建上下文）。

修法（双保险）：
- 改名 `nebula/.dockerignore` → **`nebula/Dockerfile.dockerignore`**
- 上下文根 `.dockerignore` 补齐「两个构建都不需要」的条目
  （`nebula/sample|data|data-kk|tools|docs|.env*|selfcheck*|*.md`、`.workbuddy/`、`dist/`）

实测证据（`BUILDKIT_PROGRESS=plain`）：
`#4 transferring context: 256.66kB` —— 与之相对，修之前会把 219MB 全传。

> 注意：上下文根 = 仓库根，**两个 Dockerfile 共用**。所以根 `.dockerignore`
> 只能排除「A 基础镜像构建、B 应用镜像构建都不需要」的东西；
> 只对 B 多余但 A 需要的（`src/`、`docker/`）必须留给
> `nebula/Dockerfile.dockerignore` 排除。反过来 `nebula/.dockerignore` 旧内容
> 里排除了 `docker/` —— 若它真生效反而会把基础镜像构建搞坏。

  - 删 101 项：cookie jar（`_ck*.txt`）、探针日志（`*.out`）、临时目录

### 9.4 环境坑（都已沉淀到 `~/.workbuddy/MEMORY.md`）
1. **Git Bash 对 UNC 只能读**：`ls`/`cd` 看着成功（`pwd` 也显示对了），
   但**实际没切目录、写不了文件**（`No such file or directory`）。
   → 写/删共享盘一律走 PowerShell 的 .NET API。
2. **PowerShell 的 `Remove-Item` 被安全删除钩子接管**，对 UNC 直接失败：
   `[safe-delete][SAFE_DELETE_FAIL_CLOSED] ... trash-failed`。
   → 改用 `[System.IO.File]::Delete` / `[System.IO.Directory]::Delete`。
3. **本会话 PowerShell 工具不回显 stdout**（`exit 0` 但无输出）。
   → 让脚本把结果写本地文件，再用 Read 读。
4. 大目录拷贝用 `robocopy /E /MT:16`，退出码 **0~7 都算正常**；
   不要用 `/MIR`（会删掉目标端多出来的 `技术资料/`）。
5. `Get-Item ... .Length` 对点开头文件（`.env.example`）会误报 0 ——
   实际拷贝是好的（5693 B / 122 行），**别用它的返回值做完整性判断**，
   用 `wc -c` 或比对内容。
