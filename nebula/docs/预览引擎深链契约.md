## 1. kkFileView

**官方契约（来自官网接入说明）**

```js
// 普通 http/https 文件
window.open(BASE + '/onlinePreview?url=' + encodeURIComponent(base64Encode(fileUrl)));

// 无扩展名的下载流：追加 fullfilename=xxx.ext
var previewUrl = originUrl + '&fullfilename=test.txt';
window.open(BASE + '/onlinePreview?url=' + encodeURIComponent(base64Encode(previewUrl)));
```

要点：
- `url` 参数是 **base64 之后再 encodeURIComponent**，两层。
- 拿不到扩展名（`/download?id=1` 这类）时必须补 `fullfilename`，否则 kkFileView 判断不了类型。
- base64 若用 MIME 友好型会产生 `\r\n`，`encodeURIComponent` 后变成 `%0A` 导致预览失败 —— 必须用**不带换行**的 base64。

**本项目落地**：`nebula/app/main.py` 的 `make_raw_url()` 生成带签名的直链，
再由 `/api/preview` 拼成 `onlinePreview?url=…`；直链里已带正确扩展名，
因此**不需要** `fullfilename`。

## 2. Online 3D Viewer（o3dv）★ 重点 ★

### 2.1 取证位置

`kkFileView-5.0.2.jar` → `BOOT-INF/classes/static/website/build/website_dev/o3dv.website.min.js`

关键函数（逐字摘自 min.js）：

```js
GetHash() { return window.location.hash.substring(1) }
Dr(r)     { return new Hu(r, "$") }                  // ★ 分隔符是 $ ★
Hu.prototype.GetKeywordParams = function(e){
  let t = e + "=", n = this.paramList.split(this.separator);
  for (let i = 0; i < n.length; i++) {
    let o = n[i];
    if (o.startsWith(t)) return o.substring(t.length)
  }
  return null
}
Hu.prototype.GetModelUrls = function(){
  if (this.paramList.indexOf("=") === -1) return this.paramList.split(",");
  let e = this.GetKeywordParams("model");
  return Yt.StringToModelUrls(e)
}
function In(r) {                                     // 从「模型 url」取文件名
  try {
    const url = new URL(r);
    const fullfilename = url.searchParams.get('fullfilename');   // ★ 读的是 query ★
    if (fullfilename) {
      return decodeURIComponent(
        fullfilename.replace(/^[\/\\]+/,'').split(/[\/\\]/).pop() || '');
    }
    return decodeURIComponent(url.pathname.split('/').pop() || '');
  } catch { /* 退化：按 '/' '\\' 切 */ }
}
function nr(r) { let e = In(r), t = e.lastIndexOf(".");
                 return t === -1 ? "" : e.substring(t + 1).toLowerCase() }
```

### 2.2 结论

1. **fragment 参数用 `$` 分隔**，不是 `&`。官方"分享链接"就是用 `zu`/`Pl()`
   拼 `model=…$camera=…$backgroundcolor=…`。
2. **`fullfilename` 挂在 model URL 自己的 query 上**，不和平级的 `model=` 并列：
   `In()` 接到的入参是 **model 的值**（一个 URL），所以它只能从那个 query 里读。
3. **o3dv 只按扩展名判断"能不能导入"**（`nr()`）。扩展名一丢就报
   `No importable file found`；扩展名在但内容解析失败则报 `Failed to import model`。
4. 取文件名时 `decodeURIComponent` 会**再解一次**，所以写入侧 `encodeURIComponent`
   是必须的（否则 `#`、空格会截断 fragment）。

### 2.3 两种可用写法（均已用生产数据跑通验证）

```
① 本项目现用（& 平级）
   #model=<encodeURIComponent(直链)>&fullfilename=<encodeURIComponent(文件名)>

② 官方形式（$ 分隔 + fullfilename 进 query）
   #model=<直链>&fullfilename=<encodeURIComponent(文件名)>
   #model=<直链>$camera=…$backgroundcolor=…
```

差异说明：`&` 恰好是合法 query 分隔符，`In()` 的 `new URL()` 能正确从
`…&fullfilename=%2Fxxx.STEP` 里取到值，所以 ① **功能上等价且已通过验证**。
若将来要传 `camera`/`backgroundcolor` 等**第二个** fragment 参数，必须改用 `$`，
否则 `&` 会把它们误并进 model URL。

### 2.4 验证方法（可复现）

```bash
# 1) 复刻 min.js 的解析语义，喂生产真实 fragment，看能否取出正确文件名与扩展名
python nebula/tools/_cadtest/o3dv_contract_proof2.py
#    期望：① PASS  ② PASS  ③(原版未编码) FAIL —— 第三条复现了当初那个 bug
```

实测输出（节选）：

```
① 现方案（& 平级 + encodeURIComponent）  => ✅ PASS   name='1.2.14.TFDF-6# F向.STEP' ext='step'
② 官方方案（fullfilename 进 query）      => ✅ PASS   name='1.2.14.TFDF-6# F向.STEP' ext='step'
③ 原版 kkFileView（未编码）             => ❌ FAIL   name='1.2.14.TFDF-6'          ext='tfdf-6'
```

③ 正是历史上"`#` 把文件名截断、扩展名丢失"的真因。

## 3. CAD 查看器（cad-viewer）

### 3.1 取证位置

容器 `maple-cad-viewer` → `/app/cad-client.js:195-239`：

```js
function openFromQuery () {
  var params = new URLSearchParams(location.search)
  var src = params.get('open')                 // ★ 读 query 的 open ★
  if (!src) return
  var name = params.get('name') || fileNameFromUrl(src)   // ★ name 可选 ★
  ...
  fetch(src, { credentials: 'same-origin' })   // ★ 浏览器自己拉，同源 ★
    .then(r => r.blob())
    .then(blob => { /* 塞进 <input type=file> 再派发 change */ })
}
```

### 3.2 官方契约

```
/cad/?open=<图纸可下载 URL>&name=<文件名>
```

要点：
- 参数在 **query string**（`location.search`），不是 fragment。
- `name` 可省略，省略时从 URL 末段推断 —— 但**推荐显式传**，否则带 `#` 的名字会丢扩展名。
- `fetch` 由**浏览器**发起，且要求 `same-origin` ⇒ `open` 必须
  (a) 浏览器可达，且 (b) 同源（或带 CORS）。

### 3.3 本项目落地 —— **已走官方路径** ✅

`nebula/app/main.py` 的 `api_cad_preview()`：

```python
internal     = urlsplit(make_raw_url(mount, path, ttl=3600))
public_raw   = f"{_origin(request)}{internal.path}"      # host 换成浏览器侧
if internal.query: public_raw += f"?{internal.query}"
q   = urlencode({"open": public_raw, "name": p.name})    # —— 官方两参数
url = f"/cad/?{q}"                                        # 同源反代前缀
```

逐条对齐官方要求：

| 官方要求 | 本项目做法 | 结论 |
|---|---|---|
| 参数走 `location.search` | `f"/cad/?{q}"` 用 `?` 拼 query | ✅ |
| `open` 浏览器可达 | host 用 `_origin(request)`，**不用** `NEBULA_BASE_URL` | ✅ |
| `fetch` 需要同源 | `/cad/*` 反代到 cad-viewer，同源 | ✅ |
| `name` 显式传 | `urlencode({"name": p.name})` 自动转义 | ✅ |

> ⚠️ **最容易踩的坑**：如果 `open` 用了 `NEBULA_BASE_URL`（`http://nebula:8088`），
> 服务端一切正常，但浏览器解析不了 docker 内部名 → 图纸页 `Failed to fetch`。
> 这与当初 kkFileView 的 `X-Base-Url` 是同一类问题，代码里已注释标明。

## 4. OnlyOffice

**官方契约**：后端按 DocEditor 配置构造文档对象，前端 `new DocsAPI.DocEditor()`：

```json
{
  "document": { "fileType": "docx", "key": "<每次修改都不同的唯一键>", "url": "<文档直链>", "title": "xx.docx" },
  "documentType": "word",
  "editorConfig": { "callbackUrl": "<保存回调>", "mode": "edit", "user": {…} },
  "token": "<JWT，若开启>"
}
```

要点：
- `url` 由 **OnlyOffice 服务端容器**回拉 ⇒ 必须用**容器间**可达地址（本项目 `_internal_origin()`）。
  这与 cad-viewer 正好**相反**（后者由浏览器拉，必须用浏览器侧地址）。
- `key` 必须在文档内容变化时改变，否则会命中缓存拿到旧版本。
- `mode: "edit"` 需要 `callbackUrl` 才能写回；只读用 `"view"`。

**本项目落地**：`_internal_origin()` 用于 OnlyOffice 的 `document.url`，
`_origin(request)` 用于 cad-viewer 的 `open` —— 两个 origin 的用途在代码里分开，
**不要混用**。

---

## 5. 两个 origin 的用途对照（本项目最容易混淆的点）

| 常量 | 值示例 | 谁在用它解析地址 | 用途 |
|---|---|---|---|
| `_internal_origin()` | `http://nebula:8088` | OnlyOffice / kkFileView（**容器**） | 容器间回拉文件 |
| `_origin(request)` | `http://127.0.0.1:8089` | cad-viewer（**浏览器** WASM）、kkFileView 页面 | 浏览器 fetch / iframe |

判断法则：**谁发起 HTTP 请求，就用谁能解析的 host。**
- 服务端发起 → `_internal_origin()`
- 浏览器发起 → `_origin(request)`
